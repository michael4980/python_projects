# Бункер онлайн — исследование и черновой дизайн

Статус: черновик для обсуждения (2026-10-19). Проект планируется вынести в отдельный приватный репозиторий.

## 1. Как устроена игра (по итогам исследования)

**Суть.** После глобальной катастрофы есть бункер, в котором мест меньше, чем людей
(обычно половина от числа игроков). Игроки по очереди раскрывают свои характеристики,
убеждают остальных в своей полезности и голосованием изгоняют лишних.

**Карты персонажа** (набор зависит от издания, базовый состав):

| Карта | Примеры |
|---|---|
| Профессия | врач, инженер, военный, фермер, повар, психолог, учитель, программист, безработный |
| Биология (пол, возраст, иногда ориентация/фертильность) | мужчина 34 года, женщина 61 год, бесплодие |
| Здоровье | идеально здоров, астма, диабет, ВИЧ, рак 2-й стадии, инвалид-колясочник |
| Хобби | охота, садоводство, бокс, покер, вязание, альпинизм |
| Багаж | аптечка, оружие, семена, генератор, гитара, ящик вина |
| Факт | бывший заключённый, знает 5 языков, пережил кому, клептоман |
| Фобия (в ряде изданий) | клаустрофобия, боязнь темноты, агорафобия |
| Особое условие / карта действия | поменяться профессией, отменить голосование, забрать карту у игрока |

**Карты сценария.** Катастрофа (ядерная война, пандемия, метеорит, химическая
катастрофа, ледниковый период, ...; 20 видов в последних изданиях), бункер (сколько лет
сидеть, что в нём есть: еда, вода, спальные места, 5 случайных «комнат»), иногда угроза
(событие, которое выжившие должны пережить в конце).

**Ход партии.**
1. Объявляется катастрофа и описание бункера, число мест.
2. Раунд 1: все открывают профессию. Далее каждый раунд каждый игрок открывает одну карту
   по выбору и за ~30–60 сек объясняет, чем полезен.
3. Обсуждение (~1–2 мин), затем тайное голосование. Набравший больше всех голосов
   изгоняется. Ничья: оправдательная речь кандидатов и переголосование, затем случайный выбор.
4. Повторяется, пока не останется нужное число игроков.

**Концовка в существующих версиях.** В настолке «кто остался — тот выжил», опционально
карта угрозы. В онлайн‑версиях (bunker-online, shelter42, Bunker 36) итог либо не зависит
от состава, либо генерируется ИИ‑«судьёй» в виде процентов шансов и рассказа. Именно это
нам и не нравится: концовка не вытекает из того, кого выгнали.

## 2. Ключевая идея: движок динамической концовки

Концовка должна быть **детерминированной функцией** от (катастрофа, бункер, выжившие,
изгнанные) — чтобы одни и те же решения давали один результат, и можно было спорить,
«а если бы оставили врача».

### 2.1 Потребности сценария
Каждая катастрофа и каждый бункер задают набор потребностей с весами, например:

```
ядерная война:
  медицина: 3      # лучевая болезнь
  техника: 3       # фильтры воздуха, генератор
  еда: 2
  психика: 2       # 3 года под землёй
  безопасность: 1
  размножение: 2   # если срок > 5 лет
бункер «подземная лаборатория»:
  техника: +1, еда: -1 (есть гидропоника)
```

### 2.2 Теги карт
Каждая карта персонажа даёт вклады в потребности (и штрафы):

```
профессия «врач»:        медицина +3
профессия «инженер»:     техника +3
хобби «садоводство»:     еда +1
багаж «аптечка»:         медицина +1
здоровье «диабет»:       медицина -1 (нужен инсулин), риск смерти персонажа
фобия «клаустрофобия»:   психика -2, риск срыва персонажа
факт «бывший военный»:   безопасность +2
биология «женщина 28»:   размножение +1 (если есть пара)
```

### 2.3 Расчёт итога
1. Для группы в бункере суммируем покрытие каждой потребности, сравниваем с требуемым.
2. По каждой непокрытой потребности движок выбирает **событие** (из шаблонов сценария):
   «На 4‑м месяце отказала вентиляция, инженера нет → ...». События выстраиваются в
   хронику по таймлайну (месяцы/годы).
3. Личные судьбы: у персонажей с рискованными картами (болезнь, фобия, конфликтные факты)
   считается шанс погибнуть/сорваться; событие приписывается конкретному персонажу.
4. Итоговый вердикт: «Выжили все» / «Выжили N из M (кто и почему погиб)» /
   «Бункер погиб» + процент шансов. Отдельно короткая судьба изгнанных («снаружи»).
5. Экран «а что если»: показать, какие потребности остались непокрыты и кто из изгнанных
   мог бы их закрыть — это и делает решения игроков значимыми.

Опционально: поверх детерминированной «хроники» можно генерировать художественный рассказ
через LLM (Claude API), но факты берутся из движка, а не придумываются.

## 3. Функционал v1 (предложение)
- Комната по коду, ведущий (создатель), 4–16 игроков, без регистрации (ник + токен в
  браузере для переподключения).
- Автораздача карт, выбор катастрофы/бункера случайно или ведущим.
- Раунды: раскрытие карты по выбору, таймер речи, обсуждение, тайное голосование,
  ничья → речь + переголосование → случайно.
- Экран персонажа (мои карты), общий стол (открытые карты всех), лог событий.
- Концовка по движку из раздела 2 с хроникой и «а что если».
- Мобильная вёрстка (играют с телефонов), русский язык.
- Позже: особые условия/карты действия, расширенные колоды, история партий.

## 4. Стек и хостинг (предложение)
- Backend: Python 3.12, FastAPI + WebSocket, состояние партии в памяти (Redis — позже,
  если нужно несколько инстансов). Контент карт и сценариев — YAML/JSON в репозитории.
- Frontend: одна SPA без сборки (Vue 3 или vanilla JS через CDN), отдаётся тем же
  FastAPI. Так проще деплоить одним контейнером.
- Тесты движка концовки (pytest) — он чисто функциональный, удобно покрывать.
- Деплой: Dockerfile + GitHub Actions. Варианты:
  1. Собственный VPS (Docker Compose + Caddy для HTTPS) — надёжно, ~2–5 $/мес.
  2. Render.com / Fly.io free tier — бесплатно, но инстанс засыпает без трафика
     (первый вход ~30–60 сек), домен вида *.onrender.com.
