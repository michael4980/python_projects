# Бункер онлайн

Дискуссионная игра «Бункер» для компании друзей в браузере. Главное отличие от других
версий — **концовка зависит от того, кого оставили в бункере и кого выгнали**: движок
считает, закрыты ли потребности группы (медицина, техника, еда, психика, безопасность,
продолжение рода и угрозы конкретной катастрофы), кто погиб и почему, что стало с
изгнанными и кто из них мог бы всё изменить. Поверх расчёта рассказчик на OpenAI
пишет художественную хронику (необязательно).

## Запуск локально

```bash
cd bunker_game
pip install -r requirements-dev.txt
uvicorn app.main:app --reload --port 8000
# откройте http://localhost:8000 в нескольких вкладках/устройствах
pytest -q            # тесты движка и правил
```

Переменные окружения (см. `.env.example`):

| Переменная | Назначение |
|---|---|
| `MASTER_CODE` | Если задан, создать комнату можно только с этим кодом. Вход по коду комнаты свободный. |
| `OPENAI_API_KEY` | Ключ OpenAI. Без него финал показывает только расчёт движка. |
| `OPENAI_MODEL` | Модель для хроники, по умолчанию `gpt-4o-mini`. |
| `ROOM_TTL_HOURS` | Через сколько часов бездействия комната удаляется (8). |

## Как играть

1. Ведущий создаёт комнату (на хостинге — с мастер‑кодом) и отдаёт друзьям код из 5 символов
   или ссылку вида `https://сайт/?code=XXXXX`.
2. В лобби ведущий задаёт число мест в бункере (по умолчанию половина игроков), сколько карт
   открывать за раунд и нужны ли особые условия. Минимум 3 игрока, максимум 16.
3. При старте всем раздаются профессия (открыта сразу), биология, здоровье, хобби, багаж,
   факт, фобия и одно особое условие. Объявляются катастрофа и бункер.
4. Раунд: каждый открывает карту по выбору (в первом раунде две) и защищается, ведущий
   запускает голосование.
   Набравший больше всех голосов остаётся снаружи. Ничья: переголосование среди лидеров,
   затем жребий. Особые условия (обмен, перераздача, принудительное раскрытие, иммунитет,
   двойной голос, лишнее место) играются до голосования.
5. Когда людей остаётся столько, сколько мест (или ведущий закрывает дверь досрочно),
   показывается концовка: вердикт и шансы группы, потребности с покрытием и вкладом каждого,
   хроника по месяцам, судьбы внутри и снаружи, блок «А что, если бы…» и рассказ.

Если вкладка закрылась, достаточно открыть сайт заново: сессия хранится в браузере и игрок
переподключается к своей комнате. Комнаты живут в памяти сервера: после перезапуска или
редеплоя они пропадают, и игра начинается заново.

## Хостинг

Приложение — один контейнер (FastAPI + WebSocket, состояние в памяти). Варианты:

- **Render.com** (бесплатно, сервис засыпает без трафика): New → Blueprint → этот репозиторий,
  используется `render.yaml` из корня репозитория. При создании Render попросит значения
  `MASTER_CODE` и `OPENAI_API_KEY` и сохранит их у себя: в публичный репозиторий ключи не
  попадают. Поменять их потом можно во вкладке Environment сервиса.
- **Свой VPS**: `cp .env.example .env`, заполнить, `docker compose up -d --build`, перед
  контейнером поставить Caddy/nginx с HTTPS (WebSocket проксируется как обычный HTTP upgrade).

## Структура

```
app/main.py       FastAPI: REST для входа и WebSocket игры
app/game.py       комната, раунды, голосование, особые условия
app/ending.py     движок динамической концовки
app/narrator.py   хроника через OpenAI поверх фактов движка
app/content/      колоды (YAML): карты с тегами потребностей, катастрофы, бункеры, особые условия
app/static/       фронтенд (Vue 3 локально, без сборки)
tests/            pytest
```
